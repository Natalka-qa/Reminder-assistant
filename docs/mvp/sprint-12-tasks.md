# Sprint 12 — V1.5: Smart scheduling (поиск свободного времени)

Источник: [nextjs-personal-scheduling-assistant-mvp-plan.md](./nextjs-personal-scheduling-assistant-mvp-plan.md), §18, **V1.5 — Smart scheduling**:

```text
Пользователь:
Найди завтра вечером час для тренировки
Система ищет свободные окна.
```

Одна фраза-пример и одна строка поведения. Продолжение [sprint-11-tasks.md](./sprint-11-tasks.md): Sprint 11 смержен (PR [#16](https://github.com/Natalka-qa/Reminder-assistant/pull/16)), итоги раскатки — PR [#17](https://github.com/Natalka-qa/Reminder-assistant/pull/17), затем PR [#18](https://github.com/Natalka-qa/Reminder-assistant/pull/18) (`/api/auth/session` без токена).

**План переписан 2026-09-26** после редизайна Calendar v2 + New task v2 (PR [#19](https://github.com/Natalka-qa/Reminder-assistant/pull/19)). Первая версия от 2026-09-25 опиралась на старую форму: диалог конфликта при создании и LLM-«Fill from text». Редизайн убрал и то и другое: форма теперь одна, с живым разбором фразы (правила, en/ru/uk) и уведомлением о пересечениях вместо диалога. Спринт строится на новой форме, поэтому **начинается после мержа #19**. Ветка `sprint-12-tasks` пересоздаётся от актуального `main` (сейчас локальная ветка стоит на `2394971` и коммитов не имеет).

**Цель спринта:** приложение само находит свободное время под задачу — с учётом других задач пользователя и (если подключён) занятости в Google Calendar. Две точки входа в новой форме и одна на Home:
1. **Фраза из плана.** «Найди завтра вечером час для тренировки» / «Find me an hour tomorrow evening for a workout» / «Знайди завтра ввечері годину для тренування» — парсер понимает просьбу найти время, форма ставит первый свободный слот и предлагает ещё пару.
2. **Уведомление о пересечении.** К «Overlaps with Dentist at 19:30.» добавляется «Free nearby: 17:30 · 20:45», слоты кликабельны. Это блок «AI suggestion proposing free slots» из старого хэндоффа, перенесённый из диалога конфликта в уведомление.
3. **«A small suggestion» на Home** перестаёт предлагать время, не проверив, что оно свободно.

Ничего не сохраняется без подтверждения: слот только заполняет дату и время, задачу создаёт кнопка «Create task».

**Правила пользователя (добавлены 2026-09-29, после проверки формы).**
- Поиск предлагает время **с 08:00 до 21:00**.
- **Тренировка начинается не позже 20:00.**
- **По будням 09:00–17:00 — работа.** В эти часы предлагаются только задачи, которые можно сделать в рабочее время («удалённые»: позвонить, написать, оплатить…).
- Часы хранятся **в настройках пользователя** (`/settings`). Тип задачи определяется **по словам**, с переключателем «Can do during work hours» в форме (см. «Расхождения» п.11–13).

**Sprint Definition of Done** — прогон 2026-09-29 на `dev`, подробности в S12-08. Пункты про форму и Home проверены на уровне сервисов и тестов; глазами со входом — ещё нет.

- [x] Предложенный слот **никогда** не даёт уведомления о пересечении, если его выбрать. Поиск использует тот же предикат (`hasOverlap`), те же статусы (`SCHEDULED`/`SNOOZED`) и ту же занятость Google, что проверка пересечений.
- [x] «Find me an hour tomorrow evening for a workout», «Найди завтра вечером час для тренировки», «Знайди завтра ввечері годину для тренування» → название «Workout» / «Тренировки» / «Тренування», 60 мин, завтра, время — первый свободный слот вечера по настройкам (18:00–21:00), тренировка — с началом не позже 20:00, под When ещё до 2 вариантов. Свободного нет — сообщение «No free hour tomorrow evening.», остальные поля заполнены. На один поиск — один запрос `freeBusy`.

- [x] «A small suggestion» на Home предлагает время, свободное от всех задач дня; если такого нет, карточка не показывается.
- [x] Google Calendar не подключён или флаг выключен — поиск работает по одним задачам, без запросов к Google. Google недоступен — поиск по задачам плюс пометка «Google Calendar wasn't checked»; ничего не падает.
- [x] На `/settings` работают «Start of day» / «End of day» (по умолчанию 08:00 / 21:00) и «Work hours» (по умолчанию пн–пт 09:00–17:00). Поиск и «Free nearby» их соблюдают.
- [x] В рабочие часы предлагаются только задачи, отмеченные «Can do during work hours». Переключатель по умолчанию включается по словам («позвонить», «написать», «оплатить», «call», «email»…).
- [x] Новые тесты — только на чистую логику: окна дня, поиск слотов, порядок, DST, фразы поиска на трёх языках, рабочие часы, тип задачи по словам. Реальный Google API не вызывается и не мокается.

### Расхождения плана / решения на этот спринт

1. **Ядро — детерминированный поиск.** Свободные окна — обычный алгоритм по интервалам, и его результат должен совпадать с тем, что потом проверит уведомление о пересечениях. Поэтому: чистая функция поиска + сервис, собирающий занятость. Парсер лишь превращает «завтра вечером час» в параметры поиска.
2. **Границы дня — те же 07:00–22:00, что у шкалы календаря.** Константы уже есть: утро 07:00–12:00, день 12:00–18:00, вечер 18:00–22:00 (значения на ревью). Настраиваемые «Start of day / End of day» — миграция `User`, action и UI; с текущими заглушками 09:00–18:00 «вечер» не нашёлся бы вовсе. Отдельным шагом (см. «Не входит»). **Заменено 2026-09-29 п.11:** границы дня теперь из настроек пользователя.
3. **Найденный слот ставится в форму, а не сохраняется.** Для фразы-поиска первый свободный слот сразу становится датой и временем задачи (Enter работает как всегда), остальные показываются чипами. Ручная правка всё так же важнее. Гибкость остаётся **Flexible**: время выбрало приложение, а не пользователь. Для «Free nearby» слот ставится только по клику. *(Принято 2026-09-29: авто-подстановка первого слота.)*
4. **Шаг 15 минут, выравнивание по локальному времени, не раньше «сейчас».** Для фразы-поиска — до 3 самых ранних слотов; для «Free nearby» — до 2 ближайших к выбранному времени в обе стороны.
5. **Занятость = задачи + Google, Google — по возможности.** Задачи — `findOverlapping` по окну поиска. Google — один `getBusyIntervals` на поиск, если флаг включён и календарь подключён. `unavailable` → поиск по задачам плюс пометка. Тот же принцип деградации, что в Sprint 11.
6. **«Free nearby» — в уведомлении, без второго запроса к Google.** `findExternalBusy` уже запрашивает окно ±24 ч вокруг задачи: начинаем возвращать сырой `busy`, и `previewOverlapsAction` ищет слоты по нему. Задачи в этом окне — один дополнительный запрос к БД, только когда пересечение есть. Показывается для любой гибкости: это подсказка, а не перенос. *(Принято 2026-09-29: для любой задачи.)*
7. **Фраза-поиск в парсере — отдельная группа правил, первая по порядку.** В каждом языке — триггер («find (me) (a) (free) time/slot/hour», «найди (мне) (время/окно/час)», «знайди (мені) (час/вікно/годину)»). Только в режиме поиска часть дня («evening», «вечером», «ввечері») ограничивает окно, а не остаётся в названии. Результат — `timeSearch: { dates, partOfDay }` вместо `time`. Ловушка: «час» по-русски — hour, по-украински — time; выбор языка по числу совпадений это различает, но нужен тест. Названия остаются в той падежной форме, в какой написаны («для тренировки» → «Тренировки»): морфологии у парсера нет.
8. **Отдельной кнопки «Find a free time» в форме нет.** В NEW_TASK_V2_UPDATE.md её нет («Ask before adding»); фраза и «Free nearby» закрывают сценарий. *(Принято 2026-09-29: кнопку не добавляем.)*
9. **Home — только задачи, без Google.** Слот для гибкой задачи ищется по уже загруженным `todayTasks` — ни одного запроса на рендер Home. Текст «keeps both» остаётся верным. Не нашлось слота — нет карточки.
10. **Реальные API не тестируются** — как в Sprint 8–11. Живая проверка — вручную на `dev`.
11. **Дневное окно и рабочие часы — настройки пользователя (решение 2026-09-29).**
    - «Start of day» / «End of day» на `/settings` из заглушек становятся настоящими, по умолчанию 08:00 / 21:00.
    - Новая строка «Work hours»: дни и часы, по умолчанию пн–пт 09:00–17:00; без выбранных дней рабочих часов нет.
    - Миграция `User`, аддитивная, со значениями по умолчанию: существующие пользователи сразу получают 08:00–21:00 и пн–пт 09:00–17:00.
    - Части дня внутри окна: утро — от начала дня до 12:00, день — 12:00–18:00, вечер — от 18:00 до конца дня.
    - Шкала календаря (07:00–22:00) не меняется: она показывает всё, что есть.
12. **Тренировка начинается не позже 20:00 (решение 2026-09-29).** Это ограничение на **начало**, не на конец: часовая тренировка может быть 20:00–21:00. **Уточнено 2026-09-29:** у разных пользователей разные режимы работы и активностей, поэтому это тоже **личная настройка** «Workouts start by» — по умолчанию 20:00, можно выбрать «No limit». Слова, по которым узнаётся тренировка, общие.
13. **Тип задачи — по словам + переключатель (решение 2026-09-29).**
    - Категорий у задач в модели нет, и тип не хранится: он нужен только поиску.
    - Парсер узнаёт по словам названия «тренировку» (тренировка/тренування/зал/бег/йога/workout/gym/run…) и «удалённую» задачу (позвонить/написати/оплатить/call/email…).
    - В форме, пока показаны найденные слоты или «Free nearby», есть переключатель «Can do during work hours». По умолчанию он включён для удалённых задач и выключен для остальных.
    - Выключен — рабочие часы по будням для поиска заняты. Включён — свободны.

### S12-01 · Поиск свободных слотов (чистая логика)

**Что сделать**
- `src/features/scheduling/free-slots.ts`:
  - `PARTS_OF_DAY` (`morning` 07–12, `afternoon` 12–18, `evening` 18–22, `any` = весь день) — на тех же `TIMELINE_START_HOUR`/`TIMELINE_END_HOUR`; `SLOT_STEP_MINUTES = 15`;
  - `searchWindows({ dates, partOfDay, timezone })` → интервалы UTC по каждой локальной дате (через `zonedDateTimeToUtc`);
  - `findFreeSlots({ windows, busy, durationMinutes, notBefore, limit, order })` → слоты `{ start, end }`. Начало выровнено по шагу в локальном времени, слот целиком внутри окна, `start ≥ notBefore`, ни с чем не пересекается по `hasOverlap`. `order: "earliest"` или `{ nearestTo: Date }` (поочерёдно до и после, ближняя сторона первой; см. «Реализация» ниже).
- Тесты — в этом же шаге.

**Acceptance criteria**
- [x] Слот из `findFreeSlots` не пересекается ни с одним busy-интервалом по `hasOverlap`: проверено на наборе случаев, включая задачи 0 мин и касание краями. (2026-09-29: отдельные тесты на касание, 0-минутные задачи и слот 0 мин, плюс свойство на 200 псевдослучайных раскладах с фиксированным seed: ни одного пересечения, все начала на отметках 15 мин.)

## 5. Риски

| Риск | Влияние | Что делаем |
|---|---|---|
| Слот и проверка пересечений разойдутся | Выбрали слот → «Overlaps with …» | Один предикат `hasOverlap`, те же статусы, та же занятость Google; инвариант в DoD и тестах |
| Парсер примет обычную фразу за поиск | Вместо времени — поиск | Триггер обязателен («найди/знайди/find»); часть дня без триггера ничего не задаёт; негативные тесты |
| «Час» — hour (ru) vs time (uk) | Неверная длительность | Выбор языка по совпадениям; отдельный тест |
| Google меняет занятость между поиском и созданием | Слот стал занят | Штатно: уведомление о пересечении пересчитывается при каждой смене времени |
| Границы дня не подходят пользователю | «Вечер» 18–22 не совпадает с ожиданием | Значения на ревью; настройка отдельным шагом |
| DST и нестандартные смещения | Слоты «съезжают» с :00/:15 | Выравнивание в локальном времени; тест на 2026-10-25 |
| Refresh token Google на `dev` из Testing (7 дней) | Живая проверка упрётся в «not connected» после ~2026-10-02 | Переподключить один раз (S12-00) |
