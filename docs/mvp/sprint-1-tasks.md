# Sprint 1 — Foundation: задачи

Источник: [nextjs-personal-scheduling-assistant-mvp-plan.md](./nextjs-personal-scheduling-assistant-mvp-plan.md), раздел §19 «Sprint 1 — Foundation» и backlog §22 (MVP-001…MVP-004).

**Цель спринта:** пользователь может войти в приложение, у него есть профиль с таймзоной, есть базовый layout и защищённый пустой `/dashboard`.

**Sprint Definition of Done**

- [ ] `npm run dev` и `npm run build` проходят без ошибок и warning'ов от lint/typecheck.
- [ ] Локальная PostgreSQL поднимается одной командой, миграции применяются с нуля на чистой БД.
- [ ] Новый пользователь проходит путь: `/` → `/login` → вход → onboarding таймзоны → `/dashboard`.
- [ ] Неаутентифицированный запрос к `/dashboard`, `/tasks`, `/settings` редиректит на `/login`.
- [ ] Таймзона пользователя хранится в БД и меняется в `/settings`.
- [ ] Логика авторизации не размазана по компонентам: единая точка `verifySession()` / `getCurrentUser()`.
- [ ] Приняты и зафиксированы ADR-001 (структура проекта) и ADR-002 (библиотека работы со временем).

### Расхождения плана с реальностью, которые надо решить в этом спринте

1. **Структура.** План (§9) предлагает `src/`, скаффолд создал `app/` в корне → ADR-001 (задача S1-02).
2. **Модель User.** Prisma-модель в плане (§10) не содержит таблиц, которые требует `PrismaAdapter` для Auth.js (`Account`, `Session`, `VerificationToken`). Нужен выбор стратегии сессии: JWT (таблицы не нужны) или database (нужны) → решается в S1-05.
3. **`timezone String` без `@default`** в плане (§10) — на непустой БД такая миграция упадёт, и при OAuth-регистрации значение неизвестно до первого запроса из браузера → S1-06 + S1-15.
4. **Next 16: `middleware.ts` переименован в `proxy.ts`** (старое имя помечено deprecated). Защиту маршрутов сразу писать в `proxy.ts` → S1-11.
5. **Layout не является границей безопасности** (layout не ре-рендерится при навигации и не управляет рендером вложенных сегментов). «Базовый layout» из плана не должен быть местом auth-проверки — проверка живёт в DAL/страницах → S1-10, S1-12.

### S1-06 · `User.timezone`: поле, дефолт, репозиторий

**Backlog:** MVP-004 · **Оценка:** 2 ч · **Зависит от:** S1-05

**Что сделать**
- `timezone String @default("UTC")` — план описывает поле без дефолта, но при OAuth-регистрации таймзона на сервере неизвестна, а миграция на непустой БД без дефолта упадёт. Реальное значение проставляется в onboarding (S1-15).

- `src/features/user/user.repository.ts`: `findById`, `updateTimezone`; `src/features/user/user.service.ts`: `setTimezone(userId, tz)` с валидацией. Компоненты и actions обращаются только к сервису.

**Acceptance criteria**
- [ ] Невалидная зона отклоняется сервисом с типизированной ошибкой, в БД не пишется.
- [ ] Новый пользователь всегда имеет непустую таймзону.
- [ ] Prisma-вызовы для пользователя есть только в репозитории (проверяется grep'ом).

### S1-10 · Session DAL: `verifySession`, `getCurrentUser`
