# ADR-001: Project structure

## Status

Accepted

## Context

The scaffold generated by `create-next-app` placed `app/` at the repository root. The master plan (`docs/mvp/nextjs-personal-scheduling-assistant-mvp-plan.md`, §9) proposes a `src/` layout instead, with a specific folder skeleton under it (`app`, `components`, `features`, `lib`, `types`). At the time this decision was made the project had only 4 files, so the cost of moving now is minimal; it grows with every file added afterward.

## Decision

Adopt `src/` as the root for all application code, matching §9 of the master plan:

```
src/
├── app/
│   ├── (auth)/
│   │   └── login/
│   ├── (app)/
│   │   ├── dashboard/
│   │   ├── tasks/
│   │   ├── calendar/
│   │   └── settings/
│   └── api/
├── components/
│   ├── ui/
│   ├── tasks/
│   ├── calendar/
│   └── notifications/
├── features/
│   ├── user/
│   ├── tasks/
│   ├── scheduling/
│   ├── notifications/
│   └── recurrence/
├── lib/
│   ├── db/
│   ├── auth/
│   ├── date/
│   └── validation/
└── types/
```

`tsconfig.json`'s `@/*` alias now resolves to `./src/*`.

Route groups `(auth)` and `(app)` organize routes without adding a URL segment (confirmed against the installed Next.js 16 docs — `src/app` and route groups behave identically to a root-level `app/`).

## Layering rule

Per master-plan §23, business logic must not live in components:

```
React component → Server Action / Route → Application service → Domain logic → Repository → PostgreSQL
```

Concretely:

- **Components** (`src/app/**`, `src/components/**`) render UI and call Server Actions. They never import Prisma or `@/lib/db/prisma`.
- **Server Actions** (colocated with the page/feature that uses them, `'use server'`) validate input (Zod) and delegate to a service.
- **Application services** (`src/features/<domain>/<domain>.service.ts`) hold business rules and orchestrate one or more repositories.
- **Repositories** (`src/features/<domain>/<domain>.repository.ts`) are the _only_ place that imports `@/lib/db/prisma` for that domain.

The explicit anti-pattern from §23: a component doing "Prisma queries + scheduling + validation + business rules" directly. This is checked informally by grepping for `from "@/lib/db/prisma"` / `from "@prisma/client"` outside `src/lib/db` and `*.repository.ts` files.

## Alternative considered

Keep `app/` at the repository root (status quo). Rejected: diverges from the master plan's explicit recommendation, and the cost of moving only increases as the codebase grows — better to pay it now while the tree is small.

## Consequences

- One commit moves `app/` → `src/app/` together with the `tsconfig.json` path change, so `next dev` never resolves both locations at once.
- All new code follows the five-layer chain above; deviations require a new ADR.
